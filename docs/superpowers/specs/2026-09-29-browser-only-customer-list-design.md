# 브라우저 전용 고객 리스트 처리 설계

## 목표
고객정보를 서버로 전송하지 않고 브라우저 메모리에서만 처리하는 정식 배포 구조를 만든다. 기존의 두 엑셀 통합, 주소·직급 우선순위, 최신 날짜 선택, 고객번호 제외 대상, 검토, 엑셀 저장 기능을 유지한다.

## 범위
- 자료 1·자료 2와 설문 제외 대상 엑셀을 브라우저에서 읽는다.
- 고객번호별 통합과 담당자 선정은 브라우저 JavaScript로 수행한다.
- 결과 검토와 제외 상태 변경은 브라우저 상태에만 반영한다.
- 결과 엑셀은 브라우저에서 Blob으로 생성하고 다운로드한다.
- Vercel 배포물은 정적 파일로만 구성한다.

## 데이터 흐름
1. 사용자가 브라우저의 파일 선택기로 엑셀 파일을 선택한다.
2. 브라우저가 SheetJS 기반 XLSX 파서로 시트와 셀 값을 읽는다.
3. 매핑된 행을 기존 core 로직과 동일한 규칙으로 정규화하고 고객번호별로 그룹화한다.
4. 제외 대상의 고객번호와 제외사유를 적용해 `설문 제외` 상태를 만든다.
5. 결과를 화면에 표시하고, 검토 수정은 브라우저 상태에 반영한다.
6. 브라우저에서 XLSX 파일을 생성해 사용자의 다운로드로 저장한다.

## 보안 및 개인정보 경계
- `/api` 엔드포인트와 서버 세션 토큰을 정식 배포 경로에서 제거한다.
- 고객정보를 fetch, POST, 로그, analytics로 전송하지 않는다.
- 정적 사이트에는 가상 예제 파일만 포함한다.
- 브라우저 새로고침이나 탭 종료 시 작업 데이터는 사라진다.

## 구성 변경
- `web/app.js`: 파일 읽기, 통합, 검토, XLSX 다운로드를 클라이언트 흐름으로 연결한다.
- `web/core.js`: Python `core.py`의 정규화·우선순위·최신행·제외 적용 규칙을 JavaScript로 이식한다.
- `web/xlsx-adapter.js`: SheetJS를 감싼 시트 목록, 행 읽기, XLSX 내보내기 API를 제공한다.
- `web/index.html`: 세션 토큰 메타와 서버 API 의존성을 제거한다.
- `vercel.json`: 정적 파일만 제공하도록 라우팅을 단순화한다.
- Python 서버와 테스트는 로컬 호환용으로 유지하되 Production 경로에서 사용하지 않는다.

## 오류 처리
- 확장자·파일 크기·시트·제목 행·고객번호 열을 브라우저에서 검증한다.
- 파싱 실패, 필수 열 누락, 잘못된 날짜는 기존 메시지와 동일한 의미로 화면에 표시한다.
- 저장 실패 시 Blob 생성 오류를 사용자 메시지로 표시하고 상태를 유지한다.

## 검증 기준
- 브라우저에서 가상 자료 1·2를 읽고 고객 목록을 생성한다.
- 주소 1순위, 대표·사장·실장·팀장 2순위, 최신 날짜, 전화·휴대폰, 성·이름 분리를 확인한다.
- 고객번호·고객명·제외사유가 있는 제외 파일을 적용하고 `설문 제외` 시트로 저장한다.
- 4MB 이상 파일을 브라우저에서 읽고 30MB 초과 파일을 차단한다.
- 고객정보가 서버 요청으로 전송되지 않음을 네트워크 요청 목록과 정적 배포 구조로 확인한다.
- 기존 Python 테스트와 새 브라우저 단위 테스트를 모두 통과시킨다.

## 제한사항
- 로컬 상태만 사용하므로 새로고침 전 결과를 먼저 저장해야 한다.
- 여러 사용자의 공유 작업공간이나 서버 저장은 제공하지 않는다.
